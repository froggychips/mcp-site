mcp-skills-vault

A deterministic registry + integrity scanner for MCP servers, so installing one stops feeling like curl | bash. Sister project to mcp-trace.

Install

# One-line — no clone, no global install
npx -y @froggychips/mcp-vault scan --cwd ./my-project    # what to install for this stack
npx -y @froggychips/mcp-vault list                       # all 114 servers in the DB
npx -y @froggychips/mcp-vault audit --strict             # diff installed vs DB
npx -y @froggychips/mcp-vault verify --offline           # true offline DB-pin gate
npx -y @froggychips/mcp-vault doctor                     # local readiness check

# Prefer it on PATH? Drop the npx prefix after this.
npm i -g @froggychips/mcp-vault

# As a Claude Code skill (optional)
git clone https://github.com/froggychips/mcp-skills-vault.git
mkdir -p ~/.claude/skills
cp -r mcp-skills-vault/mcp-ecosystem-intelligence ~/.claude/skills/

Zero runtime dependencies. Node built-ins only. One JSON file is the entire database.

What you get

  • Curated DB — 114 entries across 26 categories, all with pinned versions, SPDX licenses, and trust: verified | candidate. 20 Core / 71 Recommended / 23 Experimental; 94 of 114 hand-vetted.
  • Browse it — mcp-vault list shows every entry with name / category / tier / trust / install command. Filters: --category, --tier, --trust, --query. --json for scripts.
  • Supply-chain gate that fails closed — sha512 (npm), sha256 (PyPI) and @sha256: (Docker) pins, re-verified against the live registry, with 4 advisory feeds merged (npm bulk + OSV.dev + GHSA + Snyk) before the install command is written. Anything it could not check reports UNVERIFIED rather than passing: a feed being down is not evidence that a pin is good.
  • Hash the bytes yourself — --deep downloads each artifact and hashes it locally instead of comparing the pin against metadata served by the same host as the tarball. npm’s registry signature over name@version:integrity is verified on every run (100 of 102 npm entries today), and provenance attestations are read and compared with the recorded source repository.
  • The whole dependency tree — --deps resolves it with npm install --package-lock-only --ignore-scripts (nothing installed, no package code run) and checks every package in it. Across the DB that is 19,377 transitive packages, 25 entries whose dependencies run install scripts, and 38 with a high or critical advisory somewhere in the tree.
  • What actually gets written — install writes the version the gate verified (pkg@1.2.3, pkg==1.2.3, image@sha256:…), and refuses an unpinned command. npx -y pkg resolves latest at every start, which is not the artifact anyone reviewed. --host targets Claude Code, Claude Desktop, Cursor, VS Code, or prints a TOML block for Codex.
  • Check what your hosts really launch — mcp-vault verify --installed reads the configs themselves instead of the DB, and reports unpinned commands, servers that are not in the vault, local binaries and remote endpoints as what they are.
  • Trust as dated evidence — each dimension (artifact, signature, provenance, source binding, advisories, dependencies, smoke) carries its own status and the date it was established, with its own shelf life: a hash match holds for 90 days, “no advisories” for 7. trust is derived from that, and dropped when the version moves.
  • One policy file, not seven flags — .mcp-vault.policy.json sets the bar once (unverified handling, signature and provenance requirements, licence allow/deny, minimum health, acceptable trust tiers) so CI and your shell enforce the same one. An unknown key is an error, not a no-op.
  • Behavioural smoke — mcp-vault eval --sandbox spawns a server jailed in an ephemeral container, runs the initialize → tools/list handshake, counts tools and lints each schema. A docker run entry is rebuilt from its pinned digest under the jail’s own flags, because the entry’s flags come from a file a pull request can edit. The hash proves you got the file; this proves the file starts.
  • Context budget — mcp-vault budget totals what your configured servers inject into every request, stating for each number whether it was measured from a real tools/list payload or estimated from a tool count.
  • Machine-readable — --json for every command, and verify --sarif so each finding lands on the tools_database.json line that caused it in GitHub code scanning.
  • Audit installed setup — mcp-vault audit diffs your installed servers against the DB and flags drift, untrusted entries, heavy-unbounded servers, and scope issues.
  • Doctor — mcp-vault doctor checks Node, gh, Docker, uvx, and Claude MCP config readiness without printing token values.

What this does NOT do

  • Not a sandbox. Installing an MCP server still runs that server with the permissions of your MCP host.
  • Not a runtime monitor. Vault is an install-time gate; use mcp-trace or another monitor for runtime behaviour.
  • Not proof that a server is benign. Hashes prove you got the artifact you expected, not that the artifact is safe.
  • Provenance is read, not cryptographically verified. The attestation is parsed and its claimed source repository compared with the recorded one. Verifying the sigstore bundle itself — Fulcio chain, Rekor inclusion proof — is not something this tool does, and it says so rather than implying otherwise.

Latest release

Unreleased — on master, not yet on npm

  • The gate fails closed. Anything it could not check — registry unreachable, no stored hash, a wheel-only release, an install command it cannot parse — reports UNVERIFIED and fails under --fail-unverified, instead of passing quietly.
  • --deep hashes the artifact locally rather than comparing the pin against metadata from the same registry; npm registry signatures verified on every run; provenance read and compared with the recorded repository.
  • --deps resolves the dependency tree without installing it and checks every package in it against OSV — where most install hooks actually live.
  • verify --installed checks what your hosts launch, not what the DB says; budget totals the context cost; install --host writes Cursor, VS Code, Claude Desktop or a Codex snippet.
  • Trust became dated evidence per dimension, with shelf lives, computed rather than typed. --json and --sarif for every finding.
  • CI stopped running pull-request code unprotected on the machine that holds everything, and the sandbox no longer trusts flags that come from the database.
